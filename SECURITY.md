# Security reporting

Security reporting depends on the affected project and its actual configuration.

- If the repository contains a local security policy, follow it.
- If GitHub's **Private vulnerability reporting** is enabled for the target repository, use its **Security** tab to submit a private report.
- Otherwise, request a suitable private reporting route from the project's maintainer without disclosing exploit details or sensitive information publicly.

Please do **not** put credentials, personal data, unreleased vulnerabilities, or private infrastructure details in public issues or discussions.

There is no universal response-time, support, or security-certification guarantee. A project's own supported versions and security policy take precedence.
